# lazypencil AI 向けデザイン指針

設計日: 2026-10-23

AI に形式の説明だけを渡す構成を改め、設計手順、視覚スタイル、既存部品、計算済みレイアウト、参照画像を組み合わせて提供する。エージェントの実行ループは外部ランタイムに任せ、lazypencil は同じ情報を ACP 接続と外部 MCP クライアントへ提供する。

## ガイドの言語

同梱する AI 向けガイド、スタイルの説明、操作例、ツール説明は英語で記述する。ACP と外部 MCP クライアントには同じ英語の内容を提供し、ガイドのメタデータに `language: en` を持たせる。この設計文書は実装者向けの仕様として日本語で記述する。

ガイドの言語と、ユーザーへの応答・デザイン内の文章の言語は分ける。応答はユーザーが指定した言語、指定がなければ依頼の言語に合わせる。デザイン内の文章は対象の言語・地域、既存文書、ユーザーが渡した原稿を尊重し、英語ガイドを理由に英訳しない。プロジェクトが追加する独自ガイドの言語は制限しない。

## 配布する指針

| 指針 | 内容 |
| --- | --- |
| 基本手順 | 要件整理、既存デザインの確認、構成、スタイルと部品の選択、編集、確認、報告 |
| 文字と余白 | 見出し・本文・補足の階層、読みやすい行長、余白の段階、整列、密度 |
| 色と状態 | 背景・文字・強調・境界の役割、コントラスト、状態の識別、テーマ |
| コンポーネント | 既存部品の探索、参照による再利用、上書きと元部品の変更の使い分け、スロット |
| タスク別の手順 | アプリ画面、ダッシュボード、ランディングページ、既存デザインの部分修正 |
| 操作例 | 実際の lazypencil API を使い、部品作成から配置・検証・画像確認までを示す短い例 |

各指針は ID、版、概要、本文、参照先、対応する機能・形式の版を持つ。本文と例はリポジトリで管理し、例の操作が公開 API と食い違わないようにする。全資料を毎回プロンプトへ詰め込まず、共通の短い入口とタスクに必要な資料を渡す。

初期の視覚スタイルは、独自の `standard-ui`（標準 UI）、`dense-workspace`（情報密度の高い業務画面）、`content-page`（コンテンツを中心にしたページ）を用意する。各スタイルは次の情報を持つ。

- 名前・ID・版、適する用途と画面密度。
- 背景・文字・強調・境界の色、余白・角丸・罫線・効果のトークン。
- Noto Sans JP を使う文字の階層、必要な追加フォントと代替方法。
- ボタン・入力・カードなどの部品の構成例と、編集可能な `.pen` の作例。
- 使用するフォント・アイコン・画像パックの ID とライセンス情報。

スタイルは新規作成の出発点とする。既存文書では元の変数・部品・書式を優先し、ユーザーが変更を求めた場合にスタイルを切り替える。スタイル選択自体で文書を変更せず、変数・部品の挿入は通常の編集バッチとして記録する。

### 標準 UI の初期値

`standard-ui` には次の具体値を用意する。ほかのスタイルや既存文書へ強制する値ではなく、独自の標準スタイルの出発点とする。

| 要素 | 初期値と指示 |
| --- | --- |
| 文字 | Noto Sans JP。見出しは 32・24・20、本文16、補足14、短いラベル12。太さは400・500・700を用途で使い分ける |
| 行高 | 本文は1.5、見出しは1.25。固定幅の本文には `textGrowth=fixed-width` を明示する |
| 余白 | 4・8・12・16・24・32・48 の段階を使い、同じ階層の間隔をそろえる |
| 色の役割 | 背景 `#F8FAFC`、面 `#FFFFFF`、本文 `#0F172A`、補足 `#475569`、境界 `#CBD5E1`、強調 `#2563EB`。役割を変数として定義する |
| ボタン・入力 | 基本高さ44。ボタンの左右余白16、ラベル14・太さ500・中央配置。長いラベルは実測し、無理に一行へ押し込まない |
| カード | 縦方向の自動配置、padding 24、gap 16、角丸12を基本にする |
| アイコン | Lucide を標準にし、16・20・24 のサイズを使い分ける。文書内で同じ用途の書式をそろえる |
| 配置 | 主要な領域はフレームの自動配置で構成し、繰り返す要素を部品化する。絶対配置は重ね合わせなど必要な箇所に限定する |

画面ごとに主な操作と見出しを明確にし、同じ強調を多数並べない。実際の文章とデータを使って行長と密度を確認する。参照画像がある場合は、その構成・文字の階層・素材の役割を先に読み取り、標準スタイルで上書きする前にユーザーの意図を優先する。

## AI の標準手順

1. ユーザーの目的、必要な内容、対象画面、変更範囲と参考画像を確認する。情報が足りない場合は、既存文書と文脈から補い、必要な仮定を示す。
2. 文書、変数、部品、使用可能なフォント・アイコンを読む。既存デザインでは対象画像も取得し、変更しない領域を把握する。
3. 必要なガイドとスタイルを読む。情報の優先順位、画面の構成、繰り返し使う部品とトークンを決める。
4. 大きな配置から作り、同じ種類の UI を部品として再利用する。繰り返し使う値を変数へまとめ、意味が分かるノード名を付ける。
5. 編集バッチを検証し、`get_layout` で文字のあふれ・サイズ・整列を調べる。全体画像と必要な部分画像を見て、上限の範囲で修正する。
6. 変更内容、使ったスタイル、プレビュー、未解決の診断を報告する。画像を取得できなかった場合に、目視確認済みとは報告しない。

変数は元の定義と解決値を区別し、ノードの継承テーマや属性の参照元に応じて `get_variables` を問い合わせる。取得時だけのテーマ指定で保存したテーマが変わったとは扱わない。`validate_document` の `scope: "layout"` は通常の計算と同じ診断を返し、MCP ではその計算 ID を計測・画像・診断の次ページで共用する。ページ外を含むエラーの集計を確認し、検証の完了を見た目の確認済みという意味へ置き換えない。

これは外部エージェントへ渡す作業手順であり、本体が独自に LLM を呼び出すループではない。標準手順の実施状況と検証結果は会話に残すが、デザインの美しさを自動保証するものではない。

## 公開インターフェース

| MCP ツール | 入力 | 結果 |
| --- | --- | --- |
| `get_guidance` | ガイド ID。省略時は入口 | 本文、版、必要な参照先、対応条件、内容ハッシュ |
| `list_styles` | 用途、件数、カーソル | スタイルの ID・概要・必要パック、次ページ |
| `get_style` | スタイル ID | トークン、設計上の指針、部品・作例への参照、必要パック、版と内容ハッシュ |

実際の部品の探索・読み取りには `list_components` と `read_nodes` を使う。スタイルの作例は読み取り専用の許可済みリソースとして公開し、部品の取り込みは `import_component` 操作で通常の編集バッチへ含める。Pencil の同名ツールとの API 互換は約束しない。

アプリ内 ACP では、会話の入口に `get_guidance` の短い基本指示、選択スタイル、現在の対象・添付情報を渡す。外部 MCP クライアントには `get_document` の結果とツール説明から入口を示す。MCP サーバーが外部クライアントのシステム指示を強制できるとは扱わない。

ガイド、スタイル、利用可能なパックは CLI からも `guidance`、`styles`、`style`、`fonts list`、`icons list` で取得できるようにする。利用するガイド・スタイルの版とハッシュは AI 要求の記録に含める。

アプリ内の会話では、初期指示に加え、所有する MCP サーバーから追加取得したガイド・スタイル・一覧のメタデータを要求ごとに記録する。MCP は取得結果を返す前に有限の記録へ同期保存し、会話ホストは終了・取消・失敗時にその要求の記録を凍結して会話ログへ取り込む。記録できない場合は、取得または要求の失敗として扱う。本文・作例・画像はこの記録へ複製しない。一覧の取得とスタイル本文の取得を区別し、取得記録をモデルによる理解・適用の証明とは扱わない。外部 MCP クライアントの会話記録はそのクライアントが管理する。[記録の形式と上限](agents.md#design-resource-records)

## プロジェクトによる調整

`lazypencil.toml` からガイドとスタイルを明示指定できる。優先するのは、今回のユーザー指示、プロジェクトの設計ルール、選択スタイル、標準ガイドの順とする。ツールの実際の能力・検証・保存規則は、この優先順で無効化できない。

プロジェクトのガイドはユーザーが信頼した設定だけから読み、実行ファイルとしては扱わない。本家 MCP を呼ぶ指示や存在しない機能を含むガイドは、そのまま互換ガイドとして採用しない。端末や外部エージェントのグローバル設定を書き換える必要はない。

実装では `[design]` からガイド・JSON スタイル・既定スタイルを選び、`project:ID` で公開する。利用者が `config show` で参照先を確認し、`config trust` でローカルの指示利用を承認する。指示のフィンガープリントと、作例を含むカタログ・依存のフィンガープリントを分ける。ガイド・スタイル指示・選択の変更は再承認を必要とし、作例ライブラリの通常更新やフォントだけの設定変更はデータの版として追跡する。古い計算・ページは再利用しない。入口は英語本文と各言語のプロジェクトガイドを分けて返し、CLI と TUI は同じ会話サービスから渡す。作例の全体は初期プロンプトへ詰め込まず、必要時に MCP から取得する。詳細な形式・上限・失敗時の扱いは [プロジェクト設定](configuration.md) に定める。
