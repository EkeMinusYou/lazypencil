# lazypencil フォントと対応環境

更新日: 2026-10-30（現行コードと既存検証記録の照合）

状態: 初回はmacOS Apple Siliconのみを対象とし、Linux x64／arm64とWindowsは後日対応として既存実装を保持する。標準フォントに Noto Sans JP、端末画像に Kitty Graphics Protocol と Sixel を採用する。Noto Sans JP の配布データは版・ハッシュを固定済み。ユーザーによるフォント追加は `--font`、TTF・OTF・TTC・OTC の読み取りと各フェイスの取得、基本のフォールバックを実装・試験した。プロジェクト設定のファイル・検索先・既定書体・任意代替列・言語も CLI・MCP・TUI で共通化した。ユーザー共通の `config.toml` と項目ごとのプロジェクト上書きも実装した。可変wghtと指定のカラー絵文字fixture、ファミリー単位の遅延読み込みは検証済み。再現用lockfileも実装し、下記の条件で検証した。任意の絵文字列・全可変軸・OSフォントの自動変更監視・Macの最終受け入れは残る。[現在の実装と検証](fonts.md)、[設定](configuration.md)

## フォントの扱い

既存 `.pen` が指定するフォントを尊重し、新規文書には版を固定した標準フォントを使う。OS の標準フォントだけに依存せず、プロジェクトに必要なフォントを持ち運べる構成とする。指定と異なるフォントへの置換によって、既存文書の互換性を達成したとは扱わない。

### 標準フォント

新規文書の既定フォントには **Noto Sans JP** を採用する。日本語と英数字を一つのファミリーで扱い、基本パックを本体とともに提供する。Noto 全体を同梱する構成にはせず、明朝体・等幅書体・他言語・絵文字の追加フォントは用途に応じて導入できるようにする。[公式の収録文字の説明](https://raw.githubusercontent.com/google/fonts/main/ofl/notosansjp/DESCRIPTION.en_us.html)

ユーザーは OS へフォントをインストールするか、フォントファイルをユーザーの検索先またはプロジェクト内へ配置して設定から指定できる。プロジェクト内のファイルは OS へのインストールなしで利用できる。追加したフォントは CLI・MCP・TUI で共通して使い、AI による新規作成・編集でも指定できる。専用のフォント配信サービスや一覧カタログは必須にしない。

標準パックは Google Fonts revision66a36c8c94b1a5d992ee4e7f392fccfe4945767c の可変 wght TTF を採用済み。元の9,589,900バイト、SHA-256と OFL／publisher metadata は [manifest](../resources/fonts/manifest.json) に記録し、元データとの照合・可変 weight の組版／描画を検証した。通常描画でフォントを取得・更新しない。

Noto Sans JP の配布時は OFL 1.1 の著作権表記とライセンス本文を保持し、フォント自体のライセンスを表示する。本プロジェクトの MIT ライセンスに置き換えない。[付属ライセンス](https://github.com/google/fonts/blob/main/ofl/notosansjp/OFL.txt)

### 解決順と欠損

| 順序 | 解決先 | 扱い |
| --- | --- | --- |
| 1 | CLI の `--font` | 今回の明示ファイルを優先する |
| 2 | プロジェクトのファイル・検索結果、継承したユーザーのファイル・検索結果 | 項目ごとの上書きと宣言元の相対パスを使い、OS へのインストールを不要にする |
| 3 | 同梱した標準パックの指定ファミリー | Noto Sans JP は同名のシステムフォントより固定版を優先する |
| 4 | 明示した OS のインストール済みファミリー | 要求したファミリー・スタイル・太さを照合し、組版に渡すデータを記録する |

これは同名ファミリーの探索順である。文字の不足には別途フォールバック列を使う。ユーザー・プロジェクト双方で列を省略した場合は、要求ファミリー、Noto Sans JP、その他の追加ファミリーの順とし、明示配列で置き換える。設定の項目ごとの優先順、空配列、検索の上限と物理パスの規則は [設定](configuration.md#font-precedence-and-fallback) に定める。

指定フォントが見つからない場合は、ノード・要求フォント・解決方法を診断する。TUI では代替プレビューを表示できるが、不完全な描画として表示する。CLI・MCP の通常の書き出しは既存の厳格な描画方針に従って失敗とし、明示的に部分描画を許可した場合だけ代替で出力する。代替のために `.pen` のフォント名を書き換えない。

フォールバック列は文字と言語に応じて解決し、日本語と他の CJK 言語の字形を区別する。文字や絵文字列を解決できない場合も診断する。絵文字はカラー形式・結合列・異体字セレクターを含めて検証し、OS ごとに異なる絵文字を無条件に再現可能とは扱わない。

フォントは明示的な導入操作で追加し、通常の描画でネットワークから自動取得しない。ユーザー所有のフォントをプロジェクトへ自動コピーする動作も設けず、利用者がファイルと配置先を指定する。

### 再現性と軽量性

プロジェクト設定の最上位に`font_lock = "fonts.lock.json"`を指定し、`fonts lock FILE`で明示取得、`fonts check FILE`で照合する方式を実装した。JSON版1・最大1 MiBに、設定されたフォントデータの優先順、ファミリー・スタイル・source／face hash・collection index・可変軸、既定書体・代替列・言語、標準パックの版とエンジン識別情報を記録する。通常の取得でlockfileを書き換えず、不一致は計測・描画を拒否する。変更済みの内容への更新には現在のhashを要求し、文書・設定・フォントを自動で変更しない。設定された全file faceと、その文書の生成テキストを含む実組版で観測したsystem faceを捕捉する。ローカルpathを固定しないので同じデータの移動は許す。全OS書体・全script分岐・BrowserのCSSフォントの固定とは区別する。[確定したスキーマと操作](fonts.md#reproducibility-lockfile)。625bec7の[Mac完全CI](https://github.com/EkeMinusYou/lazypencil/actions/runs/40951785256)でCLI／実MCP／TUI preview workerの照合・不一致の拒否・復元、両構成とClippy、release・共通画像・署名sourceまで成功した。実端末と公開受け入れ全体は別に残る。

SkParagraph がファイルから読み込んだフォントで組版し、その結果を計測と描画の両方に使う。OS のフォント探索と、実際のフォント選択・文字計測を分ける。[Skia のフォント読み込み API](https://api.skia.org/classSkFontMgr.html)

フォントの全データ・全グリフを起動時に展開せず、使用するフェイスを遅延読み込みし、探索結果・組版・グリフのキャッシュに上限を設ける。任意の日本語を追記できるように、既存テキストの文字だけへ標準パックを削る構成は採らない。初回探索・初回読み込み・キャッシュ利用時を分けて計測する。

同じフォント・エンジン版・設定で、改行、文字位置、ベースラインと文書サイズを比較する。アンチエイリアスなどのピクセル差は別に評価し、同じフォントだけで全 OS の画像がバイト単位で一致するとは保証しない。

`browser` ノードはページ側の CSS と Web フォントを尊重する。通常の `.pen` の標準フォントを外部ページへ強制しない。固定ページによる比較試験では同じフォントを `@font-face` で供給し、フォントの準備を取得条件に含める。

TUI の会話・メニューの文字は端末のフォントに従う。デザインの文字は Skia で画像化するため、プレビュー用のフォントを端末へインストールする必要はない。

## 対応環境と後日のクロスプラットフォーム対応

初回リリースはmacOS Apple Silicon（arm64）のみとする。CLI・MCP・TUI、JavaScript／Webページ／GLSL、フォント・保存・AI接続・画像貼付・性能・配布の元の完成条件はMacで満たす。

最低macOSは15.7.9（24G830）に固定する。51ed911の[統合CI](https://github.com/EkeMinusYou/lazypencil/actions/runs/41031176732)では、15.7.9で既定構成のbuild・core・実Chromium／WebGLを含むruntime、15.8.2（24H232）で通常consumerとreleaseが成功した。同じrelease本体のSHA-256は`b0297f24…07b0759`で、利用者向け3cc43da候補と一致する。runner名からOS版を推測せず、各jobのOperating System記録とconsumerの実行host記録を用いる。Mach-Oのdeployment宣言11.0は、それ以前のmacOSを保証する根拠にしない。保証する物理端末・Kitty／Sixelの最終受け入れは別途残る。

Linux x64／arm64とWindowsは後日対応とし、既存コード・runtime catalogue・テストfixtureと明示診断経路を保持する。通常CIではLinuxアプリをビルドせず、Linuxのディストリビューション／ABI条件は初回の完成条件に含めない。Intel Macは対象外。依存ライブラリのプリビルドが存在するだけで対応済みとは扱わない。

MacでのChromium、ソフトウェアWebGL、外部AI、パス・ロック・原子的置換・子プロセス・端末を検証する。軽量な監査・ソース梱包用Linux jobは実行ホストであり、製品の対応OSを増やすものではない。

### 端末内の画像

Kitty Graphics Protocol と Sixel の両方を初期リリースの対応対象とする。最初に Kitty を実装し、続いて Sixel を実装する。端末の応答で利用可否を調べ、設定でも選択できるようにする。OS・CPU の対応と端末の画像プロトコルの対応は別々に公開する。

Sixel では色の量子化、転送量、再描画・拡大縮小の応答も確認する。PNG 出力を画質の基準とし、端末内の表示方式による差を記録する。Macで保証する端末による画像閲覧・日本語入力・キーボード操作と、Kitty／Sixel両方のbackendの動作を受け入れ条件にする。Linuxの成功だけでMacの端末を受け入れ済みとは扱わない。画像非対応端末では既存の外部ビューアへの導線を提供する。

P0 でクロスプラットフォーム上の問題が判明した場合は、機能または環境ごとに原因と対策を記録し、対応範囲の変更が必要なら判断材料を提示する。基本設計の時点で実機確認済みとは表現しない。

### 現在の検証根拠

初回Macの最新の全工程成功は[51ed911の統合CI](https://github.com/EkeMinusYou/lazypencil/actions/runs/41031176732)で、両feature構成・通常／動的描画・フォント・native clipboard・実PTY・releaseを含む。最低OSは上記の実行結果から固定した。利用者による日本語入力・候補／カーソル・Preview操作・resize・貼り付けの5項目は受け入れ済みだが、修正後Kittyの画像欠け・点滅、Mac Sixelと保証端末の確定、最終公開は残る。標準Mac VMではKittyのOpenGL初期化が失敗する。旧3環境の[c9ffb37](https://github.com/EkeMinusYou/lazypencil/actions/runs/40679529757)とLinuxの実Kitty／Sixel画像は履歴であり、Macの実画面の受け入れを代替しない。[現在の残件](implementation-status.md#remaining-work)
