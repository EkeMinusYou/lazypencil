# .penファイルとレイアウト

`.pen`ファイルを直接編集したり、MCPで部品やレイアウトを操作したりするときの
参照資料です。対応する形式、参照の解決、上書き、寸法の計算を説明します。
操作の入力例は[MCPリファレンス](mcp.md)、描画機能は[グラフィックス](graphics.md)を参照してください。

## 形式と対応対象

対応する文書形式は`2.19`・`2.21`・`2.22`です。空の新規文書は`2.22`で作成します。
既存文書、コピーした作例、ユーザーのライブラリは元の版を保ちます。
不明な版は`UNSUPPORTED_VERSION`になります。

コメント、未知の属性、編集対象以外の内容を保持して保存します。
Pencilとの完全な互換性が必要な場合は、使う機能の対応範囲と実際の描画を確認してください。
[公式の形式仕様](https://docs.pencil.dev/for-developers/the-pen-format)も参照できます。

| 対象 | 対応する内容 |
| --- | --- |
| フレーム・グループ | 階層、配置、寸法、変形、クリッピング、透明度、効果 |
| 基本図形・パス | 矩形、角丸、楕円、円弧、リング、多角形、SVGパス |
| テキスト | フォント、太さ、字間、行高、整列、装飾、折り返し |
| 塗り・線・効果 | 複数の塗り、グラデーション、線の位置・太さ・結合、影、ぼかし |
| 画像 | PNG・JPEG・WebP、相対参照、クロップと変換 |
| アイコン | Lucide、Feather、Phosphor Regular、Material Symbols |
| コンポーネント | ローカル・外部部品、入れ子、上書き、置換、スロット、切り離し |
| 変数・テーマ | 数値・色・文字列・真偽値、別名、テーマ継承、条件付きの値 |
| 注記 | `note`・`prompt`・`context`の内容と配置 |
| 動的コンテンツ | `script`・`browser`・GLSL。[実行仕様](dynamic-content.md)を参照 |

注記や`prompt`ノードは文書内容として扱います。開くだけでAIへの依頼は実行しません。
SVGパスの描画と、SVGファイル全体を編集可能なレイヤーへ変換する処理は別です。

縦方向の文字中央揃えは`textAlignVertical: "middle"`と、旧文書の`"center"`を
同じ意味で読み込みます。保存済みの値はそのまま保持します。

## コンポーネントとライブラリ

### 参照の解決

`reusable`を持つノードが部品の定義、`ref`がそのインスタンスです。
インスタンスは参照として保存し、計測・描画時に実効値を解決します。
外部ライブラリは`imports`で指定します。

| 対象 | APIで指定する情報 | 編集の書き込み先 |
| --- | --- | --- |
| 対象文書のノード | `node_id` | `document_id`で選んだ文書 |
| インスタンスから継承した子 | ルートの`node_id`と`instance_path`のID配列 | 対象インスタンスの`descendants` |
| ライブラリの定義 | `library_alias`と元の`node_id` | 読み取り用。編集時はライブラリ自身を文書として開く |

IDは文書内で一意にしてください。別文書で同じIDを使っても、ライブラリと
インスタンス経路を含むアドレスで区別されます。APIの計算用IDを保存ノードのIDとして使わないでください。

### 上書きと置換

解決順は元の定義、内側の参照の上書き、外側のインスタンスの上書きです。
外側の明示値が優先されます。属性を省略すると継承し、上書きを解除するときは
該当キーを取り除きます。`null`は解除の記号ではありません。

`descendants`の値に`type`がなければ属性の上書き、あればノードの置換です。
子配列の指定は配列全体を置き換えます。置換後の子と両立しない下位の上書きは、
同じ編集バッチで解消してください。

継承した子の更新は、そのインスタンスだけの上書きになります。元の定義を変えるには
定義自体を指定します。継承した子を直接`move`・`delete`する代わりに、置換、
スロット操作、切り離しを使います。

切り離しは一つのインスタンス境界を通常ノードに変換します。内部の別インスタンスや
変数参照は保持します。外部スクリプトの参照元は`metadata.lazypencil.script_scope`に
保持するため、手動編集でその情報を削除しないでください。

### スロット

スロットは部品内のフレームです。候補リストは配置例を示し、候補外の子も配置できます。
インスタンスに子を追加すると、そのインスタンスの子配列として保存します。
空にするには空配列を指定し、定義の子へ戻すには上書きを解除します。

### 外部ファイルと競合

相対URIは、それを書いた元文書のディレクトリから解決します。
ライブラリ内の画像もライブラリを基準に探します。
ローカルの`file://` URLは空のホストまたは`localhost`を受け付け、
許可された読み取り領域を確認します。認証情報、query、fragmentは指定できません。
HTTP(S)画像は[画像取得の設定](dynamic-content.md#http-image-acquisition)に従います。

MCPで複数文書を扱うときは、それぞれを開いて返された`document_id`を使います。
一回の編集は一文書に適用されます。ライブラリを編集する場合も、そのファイルを別途開きます。

`revision`は文書、`dependency_revision`は参照文書・設定・フォント・素材などの
入力を識別します。計測後に入力が変わると、古いリビジョンでの編集は競合になります。
読み直してから操作してください。

画像やコードが欠けていても、構造の読み取りと部分修復はできます。
欠損先と用途は診断に表示されます。元のファイルを戻す、参照を置き換える、
対象を削除するなどの方法で修復し、描画を確認してください。
詳しくは[MCPの素材修復](mcp.md#repairing-missing-assets)を参照してください。

### 探索と取り込み

`list_components`で再利用部品を探し、`read_nodes`で詳細を読みます。
取り込みでは次を選びます。

- `link`：元の定義を参照するインスタンスを作成します。
- `copy`：必要な部品・変数・素材を取り込み、独立したIDを割り当てます。

名前が衝突するときは、明示的に名前変更か既存値の再利用を指定します。
スクリプトをコピーする場合、コード内でだけ選択する素材は`options.script_assets`へ
元スクリプトの修飾キーごとに列挙してください。コード、入力、出力の参照元は
コピー後も保持されます。[取り込みの詳細](mcp.md#importing-components)を参照してください。

## アイコン

Lucideは同梱されています。Feather、Phosphor Regular、Material Symbolsの
Outlined・Rounded・Sharpは`lazypencil icons setup PACK`で追加できます。
色とサイズは通常の属性として指定します。

Materialの`weight`は100〜700で、小数も指定でき、既定値は400です。
そのほかの軸は`FILL=0`、`GRAD=0`、`opsz=24`です。
ノードの`fill`は塗りを指定します。固定スタイルのパックでは`weight`を省略します。
名前、導入手順、ライセンスは[アイコン](icons.md)を参照してください。

## 変数とテーマ

変数には数値、色、文字列、真偽値の型があります。参照は定義元の名前空間で解決し、
型の不一致、欠損、別名の循環はエラーになります。

テーマ軸は定義配列の先頭を既定値とし、祖先から継承します。ノードで指定した軸だけを
上書きします。条件付きの変数は、条件を満たす最後の値を採用します。
一致する値も既定値もない場合は診断を返します。

`get_variables`で元の定義と解決値を調べられます。`node_id`や`property`を指定すると、
そのノードや属性の参照元とテーマに沿って解決します。取得時の`theme`指定は仮の
比較に使え、保存されません。[問い合わせ例](mcp.md#variables-and-themes)を参照してください。

## レイアウトと文字の計測

### 基本の規則

| 項目 | 解釈 |
| --- | --- |
| フレームの省略値 | 横方向、幅・高さは内容に合わせる、クリップなし |
| `layout` | `none`は自由配置、`horizontal`・`vertical`は主軸に沿って配置 |
| `layoutPosition` | `absolute`は親の自動配置から外し、明示座標を使用 |
| 自動配置の子 | 親が位置を決め、子の`x`・`y`は使用しない |
| `padding` | 一つの値、縦横の二つの値、上右下左の四つの値 |
| `gap`・整列 | 主軸の間隔と整列、交差軸の整列 |
| `fit_content` | 子の内容から寸法を決定 |
| `fill_container` | 親の寸法から決定。使えない文脈では指定フォールバックを使用 |
| 線幅 | `layoutIncludeStroke`を計測に反映 |
| `textGrowth=auto` | 内容に合わせ、自動で折り返さない |
| `textGrowth=fixed-width` | 指定幅で折り返し、高さを内容から決定 |
| `textGrowth=fixed-width-height` | 幅・高さを固定し、あふれを診断 |
| 行高 | 指定値は文字サイズへの倍率。省略時はフォントのメトリクスを使用 |

レイアウト矩形と、回転・影・ぼかしを含む見た目の範囲は別です。
絶対配置の子や影の広がりは、自動配置の内容寸法には加えません。
CSSのような暗黙の縮小やmarginも加えません。

### 計算の順序

参照・変数・テーマを解決し、固定寸法や文字の計測から幅と高さを求めます。
内容寸法と親から配分する寸法が決まったら、間隔・整列・変形を適用します。
文字の幅が変われば折り返しを再計測します。描画にも同じ組版結果を使います。

主軸に複数の`fill_container`がある場合、親の内側寸法から固定・内容寸法と
基本のgapを引き、残った非負の寸法を均等に配ります。
幅320、左右padding16、gap8のフレームに、幅40の子とfillの子二つを置く場合は、
各fillの幅が`(320 - 32 - 40 - 16) / 2 = 116`になります。

`space_between`と`space_around`は正の余白を配分します。
子が一つの`space_between`はstartとして扱います。centerとendは負の余白でも
整列し、あふれを診断します。

内容寸法とfillが循環し、固定寸法やフォールバックでも解けないときは
`LAYOUT_UNRESOLVED`になります。親や子に確定する寸法を指定してください。
計算は小数座標を保ち、表示倍率によって保存レイアウトは変わりません。
スクリプト生成との相互依存は[動的コンテンツ](dynamic-content.md)を参照してください。

### AIに返す計算結果

`get_layout`とCLIの`layout`は、次の情報を返します。

| 情報 | 内容 |
| --- | --- |
| 計算条件 | 文書・依存リビジョン、スナップショットID、テーマ、エンジンの版 |
| 識別 | ノードのアドレス、元定義、インスタンス経路 |
| 寸法 | 親座標のレイアウト矩形、文書座標への変換、見た目の境界矩形 |
| 配置 | 自動・絶対配置と寸法の決まり方 |
| 文字 | 行数、幅・高さ、ベースライン、使用フォント、欠損文字 |
| 診断 | あふれ、クリップ、解けない制約、参照やフォントの不足 |

同じ`snapshot_id`を`render`へ渡すと同じ計測を使えます。
期限切れの`SNAPSHOT_UNAVAILABLE`では、古いIDを外して新しく計算してください。
単なる重なりはエラーにせず、通常のあふれは警告として返します。

## 編集操作

`apply_operations`は複数の操作を一つの編集バッチとして適用します。

| 操作 | 指定する内容 |
| --- | --- |
| `add_import`・`remove_import` | ライブラリの別名と参照先 |
| `import_component` | 元部品、link/copy、配置先、衝突の扱い |
| `set_browser_resources` | 元のfile URLとローカルディレクトリ |
| `pack_browser_resources` | ローカルWeb素材を管理bundleへ保存 |
| `set_override`・`reset_override` | インスタンス経路と属性 |
| `replace_override` | 対象経路と置換するサブツリー |
| `set_slot_children` | スロットと完全な子配列 |
| `detach_instance` | 切り離すインスタンス |
| `set_theme` | 対象ノードと変更・削除する軸 |

同じバッチで作ったノードは、操作の`client_ref`を使い、後続操作から
`{"result_of":"client_ref"}`で参照できます。`client_ref`はバッチ内で一意にします。
保存IDと対応表は操作結果に返ります。
