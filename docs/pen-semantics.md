# lazypencil 部品とレイアウトの仕様

設計日: 2026-10-23

初期リリースで扱う部品・素材・レイアウトと、AI に返す計算結果を定める。公開仕様で明記されている規則と、未記載部分に対する lazypencil の実装規則を区別する。本家の描画結果との一致は、実装前に確認済みとは扱わない。

## 形式と対応対象

公開スキーマ `2.21` に加え、手元の本家 CLI `0.3.9` が保存した `2.19` を明示した処理対象に加える。新規文書の既定は `2.21` とし、既存文書とユーザーの参照ライブラリの版を保存時に変更しない。不明な版は読み取り専用とする。共通の実装で扱う属性は同じ意味モデルを使うが、両版の全機能の互換性を確認済みとは扱わない。保存・復元・異なる既知の版の参照と、本家の単純図形からの読み取り・編集・描画は GHA で検証する。[公式の形式仕様とスキーマ](https://docs.pencil.dev/for-developers/the-pen-format)

版を保った読み書きの最初の実証は source `a7e0c15` の自作三角形で行った。本家 CLI0.3.9 の `2.19` 文書を GHA 上の lazypencil で色変更して保存し、その実際のファイルを本家で再出力できた。変更前後とも144×144の全 RGBA 画素が一致した。コメント・未知の値・数値表記の保持、履歴復元、不明版の無書き込み、混在版の参照、生成 library の版も同じ source の macOS 試験に含む。この単純図形の結果から、全属性・全版の互換性を確定しない。

| 対象 | 初期リリースで実装する内容 |
| --- | --- |
| フレーム・グループ | 子の階層、配置、寸法、変形、クリッピング、透明度、効果 |
| 基本図形・パス | 矩形、角丸、楕円・円弧・リング、多角形、SVG パス形状と座標系 |
| テキスト | フォント、太さ、字間、行高、横・縦の整列、装飾、成長方式と言語を考慮した組版 |
| 塗り・線・効果 | 複数の塗り、線形・放射・角度・メッシュのグラデーション、線の位置・太さ・端・結合、影・ぼかし・合成順 |
| 画像 | PNG・JPEG の取り込み、相対参照、cover・contain・stretch、クロップと変換 |
| アイコン | スキーマにある各ライブラリ、名前・サイズ・色、対応する重み |
| コンポーネント | ローカル・外部の再利用部品、入れ子の参照、プロパティの上書き、置換、スロット、切り離し |
| 変数・テーマ | 型、別名、テーマの継承、条件付きの値、外部ライブラリの変数 |
| 注記・文脈ノード | `note`・`prompt`・`context` の内容・書式・配置。表示の計測規則は対応版のアダプターに置く |
| 動的コンテンツ | `script`・`browser`・`shader`。[実行仕様](dynamic-content.md) に従う |

画像は塗りとして参照する場合も含む。注記や `prompt` ノードを読むだけで AI 要求を自動実行する動作は設けない。SVG ファイル全体を編集可能なレイヤーへ変換する汎用インポーターは別の追加機能とし、アイコンの読み込み・SVG パスの描画と区別する。

## コンポーネントとライブラリ

### 参照の解決

`reusable` な定義と `ref` のインスタンスを区別し、描画時にだけ実効ツリーを作る。保存時にインスタンスを通常の図形へ展開しない。外部ライブラリは `imports` から解決し、`.lib.pen` を含む参照元を依存文書として読み取る。[公式の部品仕様](https://docs.pencil.dev/core-concepts/components)、[ライブラリ](https://docs.pencil.dev/core-concepts/design-libraries)

ノード ID は元文書の中で一意とする。内部の識別子には元文書、ノード ID、インスタンスの経路を含め、別のライブラリに同名 ID があっても衝突させない。API の参照は次のように区別する。

| 参照 | API で指定する情報 | 書き込み先 |
| --- | --- | --- |
| 対象文書のノード | `node_id` | 束縛した文書 |
| 継承した子 | ルートインスタンスの `node_id` と `instance_path` の ID 配列 | 対象文書の `descendants` による上書き |
| ライブラリの定義 | `library_alias` と元の `node_id` | この MCP 接続では読み取り専用 |

これらは lazypencil の API 上の識別方法であり、独自の識別子を `.pen` の ID へ保存しない。シリアライズされた参照名・名前空間への変換は版別アダプターに集約し、公開スキーマと適法に利用できるサンプルから確定する。未確認の参照記法を推測して保存しない。

### 上書きと置換

解決順は、元の定義、内側の参照が持つ上書き、外側のインスタンスから指定した該当経路の上書きとする。外側の明示値を優先する。プロパティの未指定は継承、上書きの解除は該当キーの除去とし、`null` を暗黙の解除記号にはしない。

`descendants` の値に `type` がない場合はプロパティの上書き、ある場合はノードの置換として解釈する。子配列を差し替える操作は配列の置換とし、暗黙に元の子と結合しない。置換したサブツリーと両立しない下位の上書きは診断し、編集では同じバッチ内での解消を要求する。[公式の上書き規則](https://docs.pencil.dev/for-developers/the-pen-format#overrides)

インスタンスの子を更新する通常の操作は、そのインスタンスだけの上書きにする。元の定義の更新には定義のアドレスを明示する。継承した子を通常の `move`・`delete` で直接移動・削除せず、置換・スロット操作・切り離しを使う。

切り離しは選択したインスタンスの実効値を通常ノードへ変換し、必要な ID と内部参照を再割り当てする。内部の別のインスタンスと変数参照は維持する。入れ子も含む全展開を暗黙に行わない。

外部のスクリプトを実体化する場合は、生成物と参照入力の解決元を `metadata.lazypencil.script_scope` v1 に記録する。これは lazypencil 独自の実行拡張であり、本家との往復描画互換を示さない。元のライブラリ・コード・素材へは引き続きリンクする。[参照元の保持](dynamic-content.md#外部スクリプトの切り離しと参照元)

### スロット

スロットは部品内のフレームとして保持し、候補リストと、インスタンスが実際に持つ子を別に扱う。候補リストを型の制約として使わず、候補以外の子も配置できる。インスタンスへの子の追加は、そのインスタンスの子配列の上書きとして保存する。空にするときは空配列を指定し、元の子へ戻すときは上書きを解除する。[公式のスロット仕様](https://docs.pencil.dev/core-concepts/slots)

### 外部ファイルと競合

相対 URI は参照を書いた元文書のディレクトリを基準にする。取り込まれた部品内の画像を、利用側文書のディレクトリから探さない。許可したプロジェクト領域と明示した検索先の中で正規化し、欠損・参照循環・型の不一致を診断する。

単一文書に束縛する MCP の規則は維持する。依存ライブラリの読み取りは許可するが、書き換える場合はその文書を対象とする別の CLI 操作または MCP 接続を使う。複数文書の一括保存は追加しない。

`get_document` は対象ファイルの `revision` に加え、参照先の版・ハッシュから作る `dependency_revision` を返す。参照解決を使う編集と `get_layout`・`render` は期待する両リビジョンを受け取り、不一致なら競合を返す。ライブラリ・変数・コード・画像・フォントパックの解決結果は計算結果の依存一覧に含める。

読み取りごとに依存ファイルを取得し、処理に使う不変スナップショットを構成する。依存が取得中に変わった場合は再取得または競合にする。保存直前にも参照解決に使った依存を再確認する。ただし、非協調の外部アプリを含む複数ファイルの原子的な変更までは保証しない。TUI は依存文書の変更も監視して計算結果を無効化する。

宣言済みの画像・コードの欠損時は、予定する参照先と用途ごとに欠損依存を記録する。診断付きの構造読み取り・部分修復を許可し、修復前からある欠損先・用途の範囲内で保存できる。欠損が途中で解消した場合も依存変更として扱う。明示的な履歴復元は過去の欠損を戻せるが、不完全な素材状態を結果へ報告する。許可領域や期待リビジョンの検査を省略する経路にはしない。ライブラリなどの残る修復範囲は [MCP の修復仕様](mcp.md#repairing-missing-assets) を参照する。

### 探索と取り込み

`list_components` は対象文書・許可済みライブラリの部品を名前・用途で検索し、元文書、アドレス、スロット、必要な変数・素材をページ単位で返す。詳細は `read_nodes` から読み、必要なら `render` で部品を確認する。

取り込みは次の二つを明示的に選ぶ。

- `link`: 依存ライブラリを登録し、参照インスタンスを作る。元の定義を複製しない。
- `copy`: 必要な部品・変数・素材の依存を取り込み、ID と参照を再割り当てする。名前の衝突は既定で拒否し、明示的な名前変更か既存値の利用を指定する。

script を含む copy は、生成元の文書から参照できる部品・変数・テーマを閉じ、コードのバイト列を保持した管理アセットと生成時の参照対応を保存する。JS の中でだけ選ぶ画像・shader・入れ子の JS は `options.script_assets` に元 script の修飾キーごとに列挙する。生成する素材をコピー先の同名ファイルへ推測して結び付けない。再コピーは既存の名前空間と素材の対応を新しいコピーへ合成する。継承した入力・コード・metadata の部分上書きは、元定義への継承を保ったまま転送する。生成時に指定する別スコープの合成と本家との往復互換は実装・検証を継続する。[実装範囲と素材の宣言](dynamic-content.md) を参照する。

組み込みの作例を利用する場合も同じ操作を使う。必要な素材は不変ファイルとして先に確定し、文書の参照を一つの編集バッチで更新する。既存ファイルの上書きや元ライブラリへの書き込みはしない。

## アイコン

`lucide`、`feather`、`phosphor` と Material Symbols の Outlined・Rounded・Sharp を対応対象とする。パックの版とハッシュを固定し、名前、データ、対応する重み・可変軸を持つマニフェストで解決する。端末のフォントには依存しない。

基本パックには新規作成用の Lucide を含め、ほかは明示的な `lazypencil icons setup <pack>` で追加できる。未導入パックを参照する既存文書は具体的な導入方法を返す。描画中に自動取得しない。対応する名前・重みの不足を別のアイコンや合成太字で隠さず診断する。

| パック | 確認したライセンス | 配布上の扱い |
| --- | --- | --- |
| Lucide | ISC。Feather 由来分の MIT 表示も含む | LICENSE 全体と由来の表示を保持する |
| Feather | MIT | 著作権表示と許諾文を保持する |
| Phosphor Core | MIT | 著作権表示と許諾文を保持する |
| Material Design Icons リポジトリ | Apache-2.0 | 採用する Symbols ファイルの条件も確認し、LICENSE・該当する NOTICE・改変表示を保持する |

取得元は [Lucide](https://github.com/lucide-icons/lucide/blob/main/LICENSE)、[Feather](https://github.com/feathericons/feather/blob/main/LICENSE)、[Phosphor](https://github.com/phosphor-icons/core/blob/main/LICENSE)、[Material](https://github.com/google/material-design-icons/blob/master/LICENSE)。実装で採用する個々のファイルと版はパック作成時に固定する。本家が配布するコピーから抽出しない。

`list_icons` はパック、名前、対応する重み、導入状態をページ単位で返す。色・サイズ・変数は通常のノード属性として解決する。ベクターデータまたは専用フォントから Skia 用の表示項目を作り、同じデータを計測と描画に使う。

初期実装では Phosphor Regular の元の名前・PascalCase・廃止名を解決し、Material Symbols の3書体は元 font の可変 `wght` 軸100〜700（小数可、省略時400）を使う。Material の残る軸は `FILL=0`・`GRAD=0`・`opsz=24` とする。ノードの `fill` は塗りであり font の FILL 軸ではない。固定パックの `weight` を合成した線幅や別の名前付きスタイルへ変換しない。対応する元データ、source/index/license の固定値と検証条件は [アイコン](icons.md) に記録する。

## 変数とテーマ

数値・色・文字列・真偽値を区別する。変数の参照は定義元の名前空間で解決し、外部ライブラリの名前を対象文書の同名変数と混同しない。型の不一致、欠損、別名の循環はエラーにする。

テーマ軸の既定値は定義配列の先頭とし、祖先から継承して、そのノードの指定軸だけを上書きする。条件付きの値は条件を満たす最後の値を使う。一致する値も既定の値もない場合は診断し、任意の値を選ばない。元の配列順を保持する。[公式の変数とテーマ](https://docs.pencil.dev/for-developers/the-pen-format#variables-and-themes)

`get_variables` は元の定義と、指定したノード・テーマで解決した値を区別して返す。部品を挿入しただけで、利用側の変数を同名のライブラリ変数で上書きしない。

実装では `library_alias` で宣言済みの名前空間を選び、`name` で正確な変数名または修飾参照を指定する。ノードを選ぶ場合は実際の祖先・インスタンスから継承したテーマを使い、既定の名前空間はそのノードの元文書とする。`property` を加えると、その属性を定義・上書きした文書の名前空間を使う。`theme` は取得時だけの仮の上書きであり保存しない。生の定義、解決値、定義元・末端の値の元、失敗した変数の診断を分け、依存・問い合わせ条件に束縛したページで返す。ページ内の解決成功を文書全体の正常性とは扱わない。[公開インターフェース](mcp.md#variables-and-themes)

## レイアウトと文字の計測

### 公開仕様に従う規則

| 項目 | 解釈 |
| --- | --- |
| フレームの省略値 | 横方向、幅・高さは内容に合わせる、クリップなし |
| `layout` | `none` は自由配置、`horizontal`・`vertical` は主軸に沿った配置 |
| `layoutPosition` | `absolute` は親の自動配置から外し、明示座標を使う |
| 自動配置下の通常の子 | 親が位置を決め、子の `x`・`y` は使わない |
| `padding` | 単一値、縦横の2値、上右下左の4値を展開する |
| `gap`・整列 | 主軸の間隔、start・center・end・space_between・space_around、交差軸の start・center・end |
| `fit_content` | 子から寸法を決める。指定されたフォールバック値も読み取る |
| `fill_container` | 親から寸法を決める。適用できない文脈では指定されたフォールバックを使う |
| 線幅 | `layoutIncludeStroke` を計測へ反映する |
| `textGrowth=auto` | 内容に合わせて広がり、自動で折り返さない |
| `textGrowth=fixed-width` | 指定幅で折り返し、高さを内容から求める |
| `textGrowth=fixed-width-height` | 幅・高さを固定し、内容のあふれを診断する |
| 行高 | 指定値は文字サイズに対する倍率。省略時はフォントのメトリクスを使う |

各項目は [公開スキーマ](https://docs.pencil.dev/for-developers/the-pen-format#typescript-schema) の対応版に結び付ける。CSS の暗黙の縮小、折り返し、margin、未定義の制約を勝手に付け加えない。レイアウトに使う矩形と、回転・影・ぼかし後の見た目の範囲を分ける。

### 計算の順序

1. 参照とテーマ・変数を解決し、静的な値を持つ実効ツリーを作る。
2. フォントと文字を解決し、折り返し前の寸法など、親の寸法によらず計測できる値を求める。
3. 固定寸法と親の制約から確定する幅を伝播し、段落を組版する。
4. 内容に合わせる寸法を子から求め、親から埋める寸法を配分する。文字の幅が変わった場合は段落を再計測する。
5. 間隔と整列から配置を求め、変形とクリップを伝播する。効果を含む見た目の範囲も求める。
6. 段落の組版結果を保持し、その同じ結果で Skia が描画する。PNG や TUI の倍率から文書レイアウトを変更しない。

JavaScript の生成結果は手順の途中へ戻して同じ計測を行う。親の寸法とコードの生成結果の循環は [実行仕様](dynamic-content.md) に従って制限する。

### 公開仕様に詳細がない部分の実装規則

次は lazypencil の初期実装規則であり、本家と一致することが確認済みの規則ではない。差が判明した場合は対応版のアダプターで修正し、文書を別の配置規則へ黙って変換しない。

- 主軸に複数の `fill_container` がある場合、親の内側寸法から固定・内容寸法の子と基本の gap を除き、残りの非負の寸法を均等に配る。自動縮小はしない。交差軸の fill は親の内側寸法を使う。
- `space_between`・`space_around` の追加の間隔は正の余白だけを配分する。単一の子に対する `space_between` は start とする。center・end は負の余白を含めて配置し、あふれを診断する。
- 内容に合わせる親の計測には、自動配置に参加する子のレイアウト矩形と padding・gap を使う。絶対配置の子や影の広がりを通常の自動配置の寸法へ混ぜない。
- 内容に合わせる寸法と fill の相互依存は依存グラフで扱う。外部から確定する寸法・固有寸法・指定フォールバックで解ける場合だけ解決し、複数解または解なしの循環は `LAYOUT_UNRESOLVED` にする。無制限の再計算や任意の固定寸法への置換はしない。
- 計算は浮動小数で保ち、文書座標を端末の文字セルや整数ピクセルへ丸めない。端末表示用の縮小は画像化の後に行う。

例えば、横幅 320、左右 padding 16、gap 8 のフレームに幅 40 の子と fill の子二つを置く場合、初期規則では各 fill の幅は `(320 - 32 - 40 - 16) / 2 = 116` になる。これは計算規則の例であり、本家との品質比較の合格基準ではない。

テキストの省略属性のうち公開仕様で既定値が明記されていないもの、空フレームの寸法、グループの負の座標を含む寸法、hug と fill の曖昧な組み合わせは、版別の意味論として初期検証で確定する。新規作成の操作例は重要な属性を明示し、暗黙値への依存を減らす。

### AI に返す計算結果

`get_layout` はノード・深さ・件数・カーソルと期待リビジョンを受け取り、次を返す。CLI の `layout` も同じ情報を使う。計算済みの `snapshot_id` を指定した場合は同じ計測結果を使い、`render` にもその ID を渡せる。期限切れなどで保持されていない場合は `SNAPSHOT_UNAVAILABLE` とし、別の計測へ暗黙に差し替えない。

| 情報 | 内容 |
| --- | --- |
| 計算条件 | 文書・依存リビジョン、スナップショット ID、テーマ、エンジンの版 |
| 識別 | ノードのアドレス、元定義、インスタンス経路 |
| 寸法 | 親の座標系のレイアウト矩形、文書座標の変換、文書座標での見た目の境界矩形 |
| 配置 | 自動・絶対配置、寸法が固定・内容・親のどれから決まったか |
| 文字 | 行数、計測した幅・高さ、ベースライン、使用フォント、欠損文字 |
| 診断 | あふれの方向と量、クリップとの関係、解けない制約、参照・フォントの不足 |

単なる重なりを自動でエラーにしない。意図したレイヤーの重なりと、文字のはみ出しを区別し、装飾の影だけで文字のあふれを判定しない。通常のあふれは警告とし、計算不能や欠損による不完全な描画とは区別する。`render` と同じ実効ツリー・段落結果から返し、画像と数値が別の版にならないようにする。

ここでの `snapshot_id` は文書・依存・テーマ・実効ツリー・段落計測を固定する計算スナップショットを指す。Web ページの取得画像には別に取得 ID を持たせる。取得画像の更新は、文字の計測結果まで変更されたことを意味しない。指定したスナップショットと異なる時刻・テーマなどの再計算を要求した場合は入力の不一致として返す。

## 編集操作の追加

以下を `apply_operations` の原子的なバッチに含める。ライブラリ定義への暗黙の書き込みは行わない。

| 操作 | 明示する内容 |
| --- | --- |
| `add_import`・`remove_import` | ライブラリの別名と参照先。利用中の参照を壊す削除は拒否する |
| `import_component` | 元の部品、link・copy、配置先、名前の衝突の扱い |
| `pack_browser_resources` | 現在の文書が宣言したローカル Web 素材を管理 bundle に固定する |
| `set_override`・`reset_override` | インスタンスの経路と属性。元部品を変更しない |
| `replace_override` | 対象の経路と置換するサブツリー |
| `set_slot_children` | インスタンス内のスロットと完全な子配列 |
| `detach_instance` | 切り離すインスタンス。入れ子の参照を維持する |
| `set_theme` | 対象ノードと指定軸。削除する軸も明示する |

バッチ内で作った部品・ノードは、操作ごとの `client_ref` を後続の `{ "result_of": "client_ref" }` から参照できる。`client_ref` はバッチ内で一意とし、未実行の操作への参照と重複を拒否する。保存 ID はエンジンが生成し、結果に対応表を返す。これにより、部品の作成とインスタンスの配置を同じバッチで行える。
