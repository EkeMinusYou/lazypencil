# GLSL fills and effects

Read an existing shader asset before editing it. Create new source with put_asset using kind: shader, then update the fill or effect URL through an atomic editing batch. Source uses WebGL 1.0 fragment GLSL, usually with an explicit precision declaration. It is compiled by software WebGL in a dedicated Chromium process and composited by Skia.

Use documentation-style block comments (/** ... */) when authoring metadata for Pencil compatibility. The nearest documentation comment (/** ... */) immediately before a uniform can bind the exact directive @resolution to a vec2, or @time to a float with the explicit render time, whose default is zero. Blank lines are allowed. Another comment, ordinary code, or a preprocessor directive between that comment and the declaration clears its metadata. An annotation after a semicolon belongs to the next declaration, including on the same line; it never modifies the preceding declaration. Annotations inside declarations do not bind. A grouped declaration shares its annotations across all declared names. Names such as @time_step do not bind built-in values. Built-ins must not be arrays or be overridden in the document. @time cannot be combined with @default. gl_FragCoord.xy uses local logical coordinates for shader fills even at enlarged output; its z/w components keep WebGL semantics. @resolution uses the logical shader extent, not the exported pixel dimensions. Effects use the logical extent of their composited image. Source macros, conditional definedness and explicit macro overrides are preserved by bounded preprocessing after the original WebGL source is validated. The saved source and its hash remain unchanged. Full Pencil compatibility beyond the reference corpus still requires verification.

Other uniforms are stored by name in uniforms: numeric float or int, boolean, numeric vectors, hexadecimal colors for vec3 or vec4, matrices, or image inputs for sampler2D. ivec2/3/4 use integers; bvec2/3/4 use numeric 0 or 1. mat2/3/4 use 4/9/16 column-major numbers. Numeric arrays use flat numeric lists: vec3 colors[2] requires six numbers. Boolean arrays use numeric 0 or 1. Literal dimensions are checked before browser startup; constant-expression dimensions are compiled by WebGL and their active elements are checked at binding. An optimized unused tail is ignored by the linker. Use complete declared values when the full dimension is known. Grouped declarations such as uniform float first, second[3]; are accepted.

A documentation comment before a uniform can set @default, for example /** @default 0.75 */ before a float declaration. Use comma-separated components for vectors and matrices; @color with vec3 or vec4 also accepts a hexadecimal color default. Grouped names share the default. Ordinary comments do not set defaults. A documentation comment after one declaration can set the next declaration's default, following the same adjacency rule. Stored values, including zero and false, take precedence; built-in resolution and time remain automatic. A numeric array default initializes its first element, with zero for remaining linked elements; this does not relax validation of explicit array overrides. Prefer decimal numbers: native decimal-prefix parsing treats 0x2 as zero. Missing numeric defaults use zero, and missing sampler inputs get a transparent image. Rendering does not rewrite metadata or saved uniform values.

Image sampler URLs resolve through captured document assets. A sampler2D array uses a list of image URLs, for example {"images":["front.png","back.png"]}. Each list element may reference a string variable, whose aliases and theme retain their own source document. Literal dimensions require exactly that many values; expression dimensions require at least the linked active prefix. The runtime binds each active element to a texture unit, reuses identical image inputs, and checks its actual fragment texture-unit limit. Lists also accept pencil:object and pencil:background when that render stage provides them. Both fixed-image lists and local relative string-variable inputs can be copied independently as described below. An effect can bind pencil:object to the already rendered node. pencil:background captures the scene before that node, including relevant parent layers. Effect order matters: each shader receives the result of previous effects. Fill-stage pencil:object is currently unavailable. Internal texture orientation is handled by the runtime; do not compensate for it by flipping ordinary input images again.

For a variable-valued image URL, lazypencil follows aliases and the active theme, then resolves local images relative to the document defining the selected value. The same variable's text uses keep their original strings. Detachment retains these linked variables and their image origins. Standalone component copying retains local relative string sampler values in ordinary imported variable libraries with captured images. Absolute local paths, local file:// URL strings, HTTP(S) URLs and conflicting path projections use managed image bindings while preserving their original text. Shared strings, aliases and themes remain editable; no managed image URL is substituted into the text value. Canonical-path, allowed-root and dependency checks still apply to local inputs. Local file URLs cannot contain credentials, a remote host, a query or a fragment; percent-encode reserved filename characters. HTTP(S) images use the captured runtime.browser network policy and timeout, capped at 30 seconds across one project's image acquisition, with 20 MiB per encoded static PNG/JPEG/WebP and at most five redirects. An owned worker handles cancellation without leaving network work behind. Each snapshot keeps its acquired bytes in memory without refetching during verification. A copied component retains those images locally, including inactive themes, so it can render after the remote server and original files are gone. HTTP image URLs cannot contain credentials, and HTTPS redirects cannot downgrade to HTTP. Browser-profile cookies are not imported. Missing HTTP images report incomplete assets and can be structurally repaired. File-URL and HTTP keys in captured script asset manifests remain unsupported; use captured local path keys there. Inspect capabilities before choosing an independent copy. Pencil parity of this imported-variable path policy is unverified.

Embedded data:image/png, data:image/jpeg and data:image/webp URLs work in image paints and string samplers, including copied script output. Use standard base64 with a trailing ;base64 header marker, or percent-encoded image bytes otherwise. The decoded encoded-image payload is limited to 20 MiB and must match its declared static-image MIME type. Offline policy does not disable these self-contained images. Copy and detach preserve the exact original URL and its text/theme uses without creating a managed image file. Do not use these URLs for scripts, shader code or library imports. Malformed embedded images remain incomplete assets with repair diagnostics; their payload is not included in those diagnostics.

Use render time to evaluate animation at a reproducible instant. Request a new time to change it. The result includes the actual browser and software renderer, enabled extensions, request hash, and PNG hash. Captured runtime.shader settings control acquisition/launch deadlines and idle expiry; runtime.dynamic controls the shared render budget and cache. Expanded declaration sources and encoded rasters share its byte/entry limits and LRU. Interface acquisition, typed preparation and drawing share one shader deadline; cached reads do not keep the browser alive. Acquisition metadata reports effective limits, and changing policy invalidates old cached rasters. Compilation, linking, invalid uniforms, missing inputs, context loss, and deadlines are errors. Generated pixels do not replace editable source code in the document.

Current limits include 1 MiB of GLSL, 262,144 declaration tokens, 256 uniform names/typed leaf patterns, 256 array elements, 4,096 supplied/active numeric components, 8,192 pixels per side, and 16 megapixels per dynamic raster. Structure expansion has at most 16 levels, identifiers at most 1,024 bytes, and qualified leaf names at most 4,096 bytes. Encoded sampler inputs are limited to 64 MiB per shader request. GLSL preprocessing has a 64 MiB memory maximum, a 4 MiB expanded-source limit, and 262,144 events. The compiler macro probe accepts at most 256 distinct GL_ names. GLSL ES 1.00 rejects direct arrays of arrays and embedded structure definitions. Already-declared structure types can be nested, including structures that contain arrays. Object/function macros and conditional branches are expanded in the bounded browser Wasm using the actual compiler's predefined macros before typed inputs are prepared. Annotations on the selected declarations retain their defaults and automatic time/resolution bindings. A preprocessor directive between a documentation comment and a declaration breaks the annotation binding, even when that directive disappears during expansion. Original source positions and line/file macros are retained. Only selected declarations accept overrides; unknown or inactive names are errors. Literal dimensions created by expansion use the normal bound checks; constant expressions still depend on the linked interface. Captured GLSL and saved values are preserved. Full Pencil parity remains unverified. Common vec2 UV varying aliases are provided, but full Pencil vertex and annotation compatibility has not been established. Inspect both the full design and relevant detail images before reporting success.

Structure uniforms use qualified leaf names in the flat uniforms object, for example {"lamp.color":"#3a7fc1","lights[1].strength":0.75}. Named, inline, anonymous and nested structure types are supported, including arrays of structures and primitive arrays inside fields. A field such as lights[1].weights is a numeric list when the GLSL field is an array. Use canonical decimal indices, starting at zero. Unset typed fields use zero or a declared field default; unset sampler fields use transparent images. Field annotations belong to their own declaration and are not inherited from a comment on the aggregate structure. Aggregate @default, @time and @resolution are rejected. A structure-array field cannot use an automatic @time or @resolution binding. Actual linked leaf types are checked before values are applied. Literal structure-array bounds are checked before launch; constant-expression bounds still depend on the active interface reported by the compiler. These structure paths use self-authored WebGL checks; the older pen.dev CLI 0.3.9 failed to export the structure probes, so its output is not a structure compatibility oracle.
