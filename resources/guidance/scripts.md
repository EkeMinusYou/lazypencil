# Script-generated designs

Use a script for parameterized geometry, charts, or repeated structures when ordinary components would be awkward. Read the node and its captured source first. read_asset returns script_header metadata or a header diagnostic alongside the source chunk. Edit the inputs or create a new immutable source with put_asset, then update scriptUri through apply_operations.

Start new source with a header comment declaring @schema 2.21. Existing @schema 2.19 and legacy @schema 2.11 headers are accepted without rewriting the source. Header compatibility is separate from supported document versions; it does not enable 2.11 document files. Declare inputs with @input name: type = default. Supported types are number, string, boolean, color, enum, and ref. Defaults are JSON values; an unquoted hexadecimal color is also accepted. Missing or null inputs use the declared default. Without one, numbers use 0 clamped to their limits, strings and refs use an empty string, booleans use false, colors use #000000, and enums use their first option. These values are transient and are not written to the document or header. Saved keys absent from the header remain in the file and are excluded from runtime input, including variable lookup. Declared values of invalid types and enum values outside the declared options are errors.

The script body receives pencil.width, pencil.height, and pencil.input and must synchronously return a node array. Use document variables in the stored inputs to bind values to themes. A nonempty ref input must select an existing reusable component; an empty ref means no selection, so branch or supply fallback geometry before generating a component instance. A null override resets to the source header's default, whose component is resolved in the script's own library. Explicit nonnull selections retain their input document's scope. Output may use existing component references, but cannot declare reusable components. Stored and generated children have separate identities: generated layout records include generated_by. To change their design, edit that source node or its code and inputs.

Use import_component with mode copy for an independent executable copy, including inherited input/code/metadata overrides; read the components guide for asset manifests and collision policies. Copying does not execute the script or freeze its current output. Unoverridden inputs and metadata still follow the copied base definition. Saved inputs and output code keep separate namespaces. An explicit input or code update switches that field to the caller's context, even for an unchanged JSON value; a null ref still requests the code header's default. Keep private binding metadata intact when retaining an existing context, and use ordinary edit/reset operations to change it.

To inspect generated properties, call read_nodes with calculated: true, or pass a snapshot_id from get_layout, render, layout validation, or an earlier calculated read. Reusing the ID reads that exact calculation without rerunning scripts. The calculated view includes resolved properties, property sources, effective themes, generated_by, and matching layout records. Select a generated node by its returned top-level id; use node_id plus instance_path for inherited script owners. Read additional pages with the same snapshot_id and returned cursor. Reduce depth or limit if the 4 MiB response budget is exceeded. Generated IDs are read-only: follow generated_by to the owning script, and change its source or inputs. Omit calculated and snapshot_id when reading stored code for repair without execution.

Execution has no DOM, filesystem, network, timers, or host module loader. Each request starts with a fresh JS context. Math.random uses Mulberry32 with seed 0 and restarts its sequence on each evaluation, independently of dimensions and inputs. Thirty-seven sampled outputs through draw 65,536 match the original public pen.dev CLI 0.3.9 reference corpus; broader script compatibility still requires verification. Defaults are 2 seconds and 64 MiB per evaluation, with a fixed 1,000-node output cap including owned nested children. Captured runtime.javascript settings control evaluation time, heap, idle reaping, layout budget and evaluation/pass counts. Inspect configuration.settings.runtime and script_executions[].limits when diagnosing a resource failure. These limits are host policy, separate from pencil.input. Exceptions, allocation failures, cycles, deadlines, and invalid output fail the calculation; catching an interpreter interruption does not make it successful. Reduce excessive work instead of silently relaxing policy to claim a successful preview.

Prefer definite sizes or parent fill sizes for scripts that read their dimensions. A content-sized dimension that the script reads needs an explicit fallback, such as fit_content(200). A script that does not read its dimensions can fit independent output geometry. Nonconvergent layouts stop with a diagnostic. Script evaluation and generation are bounded; do not solve a failed cycle by inventing an arbitrary fixed size.

On a header or JavaScript failure, inspect error.details.script_diagnostic and the captured node, script_path, and source_hash. Coordinates are one-based original-source lines and UTF-8 byte columns, including the header. Excerpts contain at most three lines of 240 characters each; start_column and truncation flags identify clipped windows. Distinguish the throwing source, a dynamic-code call_site, a header declaration, and end_of_source. A null position means no usable location was reported; do not invent a line. Exception stacks can be replaced by script code, so treat positions as debugging hints. Read the captured source when available, repair its inputs or publish a new immutable source, and run a new calculation and visual check. Keep normal revision checks; an error excerpt does not authorize editing a generated node.

When a nested failure returns failure_capture_id, call read_asset with source_hash on the same MCP connection to read its full original source in UTF-8 byte chunks. Follow next_offset until it is null. A failed_calculation response identifies a failed-code capture, not a successful layout: never use failure_capture_id as snapshot_id or claim a rendered preview exists. Captures expire after five minutes and retain at most four code files. Changed documents, dependencies or path targets invalidate the capture; recalculate to obtain a current diagnostic. read_asset cannot open arbitrary paths, and a header error does not prevent reading the captured source. If no capture is available, inspect the declared owner/source and repair through ordinary document operations without inventing access to an undiscovered file.

get_layout returns script execution hashes and runtime_dependencies for files discovered in generated content. The ordinary dependency_revision still identifies document-declared dependencies. The calculation snapshot fixes runtime dependency bytes as well; render with its snapshot_id. A changed runtime file invalidates that snapshot. Render and inspect the actual output, and report unresolved diagnostics without claiming complete Pencil compatibility.
