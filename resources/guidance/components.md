# Components and atomic editing

Search existing reusable definitions before creating another button, field, card, or repeated row. Reuse the source component when its structure and meaning fit the task. Library definitions are read-only through a document-bound connection. Do not modify a global definition when the user requested a change to one instance.

Distinguish the stored root instance, an inherited descendant, and a component definition. Inherited descendants are identified by the root instance ID and the nested instance path. Normal frame hierarchy does not create a new component namespace. Use only editing operations advertised by the current server; do not substitute an update to the root when a descendant operation is unavailable.

Read an inherited node with read_nodes using node_id and an instance_path array. Its expanded properties include variable references and property origins; get_layout supplies calculated measurements. To change only that instance, use update or set_override with the same address. reset_override restores inheritance; replace_override replaces a descendant; set_slot_children replaces a complete frame child array. Use the returned client bindings for later operations instead of guessing generated IDs. set_theme changes selected axes without replacing every inherited axis.

For resolved properties and script-generated descendants of a used instance, pass a calculation's snapshot_id to read_nodes with that inherited address. This calculated view matches the layout and PNG tree and preserves source namespaces and themes. An unused library definition still uses the ordinary library_alias query; it is outside the bound document's calculation. Generated children cannot be edited as stored overrides; edit their owning script instead.

Inspect get_document capabilities before detaching or importing a component. Stored and inherited instance detachment keeps nested references and variables. External library references stay linked, moved asset paths keep their original targets, and library variables use their original namespace. Detachment checks the resolved result before saving. External scripts retain their linked execution context through versioned metadata; treat unsupported scope-preservation diagnostics as a failed atomic batch. Keep a reference when the user wants future changes to the component definition to propagate.

An omitted property inherits its value. Removing an override restores inheritance; null is not a generic reset command. A descendant override with type is a full node replacement. Replacing children replaces the array, including the empty array; it does not merge old children. Slot suggestions help discovery but do not prohibit other valid content.

Use client_ref for a newly created element that later operations need. For example, an insert can declare client_ref `button`, and a later insert can set ref to {"result_of":"button"}. Use the returned bindings for later requests. Keep related structural changes in one batch so missing references are never persisted midway through the operation.

External script detachment retains its execution and input documents through versioned lazypencil metadata. Keep that metadata and its declared library dependencies when editing the detached node. This does not make a standalone copy of the code or library, and Pencil round-trip rendering of this extension is unverified. Use ordinary source/input edits for a new context; do not manually fabricate binding hashes.

Read the current revision and dependency revision before planning an edit. On conflict, read again and reconcile the user's intent with the actual document. Retry an ambiguous saved request with the same request ID and payload; use a new ID for a different edit.

Use import_component with an explicit mode. link creates a reference to a local or library definition; a file source also registers its import alias. copy creates local reusable definitions and closes their static component, variable, theme, image, and shader dependencies. The returned id is the placed instance; component_id identifies its reusable definition. Copied definitions are stored in a disabled frame so they do not add visible template artwork. Reuse one imported definition across repeated controls instead of importing it for every instance.

Sources can select a declared library with {"library_alias":"ui","node_id":"button"}, a project file with {"uri":"ui.lib.pen","import_alias":"ui","node_id":"button"}, or a bundled style with {"style_id":"standard-ui","node_id":"button"}. Read the style's editable example before selecting an ID. Use expected_source_revision when the source document hash is known. File sources remain within allowed project roots. copy leaves no new source import; link keeps the source live.

Copy name collisions fail by default. variable_prefix and component_prefix can give a kit its own names. Per-source variables, components, and themes maps can explicitly rename a source name or reuse a local target. Error details identify the source_key. Reused variables require the same type; reused themes must contain all source values. Reuse must also satisfy the importer's dependency constraints; do not bypass a refusal by flattening the component.

Explicit component reuse can replace a reusable definition contained in a copied parent. Its placement becomes a fresh local ref; the chosen existing definition supplies its body, appearance, metadata and code. The source's placement and dimensions stay as instance overrides, and later edits to the target remain live. id_map reports the placed ID; reused_components reports the selected definition. When descendant IDs differ, supply component_paths for that reused source key, for example {"ui:badge":{"source-label":"local-label"}}. Both paths must exist in their respective definitions. Stored children and full-node replacements keep their own authored bodies. Paths to their new children follow the effective instance boundaries, including when reuse changes a ref into an ordinary group or introduces a new ref. Stored and generated refs use the same translation. Colliding destinations fail atomically. Keep missing-path and execution-context composition errors visible; do not guess which target child the user intended.

String-valued shader image samplers with local relative or absolute filesystem paths can be copied independently. Text uses retain the exact original string; captured image origins travel with the copy. Copy captures all theme alternatives, variable aliases and required image bytes. Changing the copied variables later can select a new consumer image. Explicitly reused consumer variables retain their consumer file bindings. Ordinary relative hierarchies are preserved where possible; distinct aliases, case collisions and file/directory projection conflicts use managed image bindings when the original strings cannot share one filesystem layout. Immutable resource bundles carry hashed inventories and use guarded publication. Missing assets, unapproved schemes and paths outside the allowed roots remain errors. Do not substitute an unrelated asset or a static image for requested live behavior.

For example, a batch can import a bundled button, then place its returned instance:

```json
[
  {"op":"import_component","source":{"style_id":"standard-ui","node_id":"button"},"mode":"copy","options":{"variable_prefix":"kit.","component_prefix":"Kit "},"client_ref":"primary"},
  {"op":"update","target":{"result_of":"primary"},"set":{"x":40,"y":40}}
]
```

Inspect the imported structure, measure layout, and render the result. Source libraries and original asset files are never edited by an import. A dry run validates staged bytes without creating managed files or document history. A committed request can be replayed even after its original source is unavailable.

For script copies, the importer closes the reachable source component, variable, and theme namespaces without executing JavaScript. Code remains executable JavaScript, stored as immutable copied bytes. Add files selected only inside the code to options.script_assets, keyed by the qualified source script node, with entries such as {"kind":"script","uri":"nested.js"} or {"kind":"image","uri":"alternate.png"}. A descendant code override uses its owning ref and override path, such as ui:inner/draw. URIs use that script's original output document. Include shader source and alternative files that later input values can select. Generated paths outside the manifest fail instead of opening a same-named consumer file.

A copied generator can return a ref with a scriptUri override, directly or inside descendants. Include the replacement source in that generator's script_assets. Replacement output uses the generating script's captured namespace. Saved inputs and user metadata that are not overridden retain the referenced definition's ownership. Explicit inputs use the generating scope; null uses the replacement header's default. Ref choices use the target's effective inherited theme, including selections inside a referenced container. Changing that container's theme recomputes the choice. Controls absent from the replacement header stay unused. A matching explicit script_input_context selects its own captured variable and component maps independently of output scopes and bindings. Its library resolves in the generating document's captured libraries. Inactive input contexts do not resolve their target libraries. Combined script_override carriers and inherited inputs from different capture generations still need further composition; keep their unsupported-feature diagnostic visible.

Generated script_scope and script_bindings may coexist. Their URI guards are independent: an active binding takes precedence for output. For saved ref choices, a matching active binding's inputs_hash takes precedence over script_scope.inputs; otherwise the matching scope input library applies. Without either input guard, explicit inputs retain the generating document's ownership and inherited inputs retain their previous owner. Variable expressions keep their input owner's variable table even when component choices select another scope. Guarded inherited inputs must retain lexical ownership from the same captured generation; independent explicit input overrides and legacy captures without that ownership still need further composition. A stale selector does not authorize an unknown namespace, and an active invalid selector remains an error even when another selector takes precedence.

Generated refs and descendant overrides can use a dedicated script_override envelope. Its metadata contains ordinary user metadata and the underlying scope, binding and input context. Its output and input replace those sides independently; a null field preserves the underlying selection. A stale input replacement clears that explicit input context while retaining an active scope or output binding's input mapping. A stale output replacement with an explicitly supplied scriptUri restores the generating document's output namespace. When the URI is inherited and its original code owner is unavailable, keep the diagnostic rather than guessing that owner. A nested script_override inside the envelope's user metadata remains ordinary metadata and is not recursively applied. Full script definitions do not use ref override envelopes.

Copied script definitions retain code_namespace separately from their active output namespace. It names a document in the shared captured graph, including the code's declared libraries and closed assets, and survives another independent copy. When an inherited URI keeps its code but an output scope, binding or carrier becomes inactive, output returns to this captured code owner. Ordinary metadata edits still preserve the active output selection. This field is internal provenance, not a filesystem path or user-facing selector. Legacy captures and generated replacements without that provenance require copying again from an available source when code ownership is needed.

Newly emitted scripts also capture the document used to resolve their code, before applying their own output scope. Later descendant overrides preserve this already composed context while resolving their target. When code and output use different captured graphs, the code's reachable libraries and their component paths, variables, themes, assets and browser bindings are merged without replacing the output graph. Colliding names receive separate internal keys. Missing legacy document provenance still produces a diagnostic.

Copied input context version 3 also retains generations keyed by the producer's input_epoch. Each snapshot keeps the original controls, their lexical variable and component maps, and the underlying scope and binding component maps. Another copy remaps the targets while preserving the original controls and generation keys. An inherited input override is checked against the producer's generation, so old and newly authored generators can share a copied definition without sharing its lexical input owner. A stale explicit input context restores that generation's lexical controls and the applicable underlying scope or binding; an output-only override preserves the existing explicit input context. These fields are internal provenance. Missing legacy provenance remains an error, and captured targets and per-script/output budgets still apply.

For a generated script, script_scope can select a captured declared library for its output. This also applies to a ref or descendant metadata edit that inherits its source URI. The input hash selects an independent input library when supplied or inherited raw input expressions match. URI and input guards use captured original spelling across copy and recopy; relocation and renamed variables cannot reactivate stale guards. Unchanged inputs keep their inherited owner unless their input guard activates. A copied input context retains variable and component ownership independently. Unknown active aliases never fall back to consumer files or same-named consumer components. JavaScript bytes remain unchanged. New bindings version 3 retain the original URI hash, and input contexts version 2 retain a hash and sparse original expressions. Versions 1 and 2 bindings and version 1 input contexts still read; an inherited guard requiring unavailable legacy provenance reports a diagnostic and needs regeneration from its source. Custom script_bindings translate logical names, target-identity fallbacks, descendant paths, themes and asset aliases through captured tables. Their library selects the output binding targets; a matching inputs_hash independently selects input_components for saved ref choices. Unknown targets and unmanifested files fail. Custom captured views retain their declared scope graph. Nested custom-owner composition and combined override contexts still need further verification and composition; preserve their diagnostic instead of changing the requested ownership.

Version 4 bindings separate a native binding's logical output map from its underlying document namespace. A parent's aliases rewrite that parent's generated properties; nested code without its own mapping uses the captured document. A nested native binding or explicit scope selects names in that document, rather than applying the parent's aliases again. Captured native views retain source_variables so supplied input guards compare the original expression after the parent's single rewrite, before copied variable names change it. Inherited controls keep their own original expressions and input owner. Input guards select ref choices while variable expressions keep the document that supplied them; stale guards stay inactive even when the source guard differs. Older captures without this provenance require recopying only when original native variable spelling is needed. Additional generated files belong to the binding's resolved owner, which can differ from the document storing scriptUri. Copies retain both tables and recopy both without changing JavaScript; versions 1 through 3 remain readable. The document namespace is generated bookkeeping, not a filesystem path. Combined envelopes remain unfinished.

Copied string image variables keep their original text and image origin together; editing the copied variable can select a new consumer image without freezing a separate image-only value. Nested scripts use captured execution namespaces within bounded output budgets. Re-copying a bound script composes its existing component, saved-input, variable, theme, descendant and asset maps into the new copy without changing JavaScript. This keeps both original names and previous target identities usable after source removal. Additional assets can be supplied again; conflicting preserved asset names are rejected. Binding construction is bounded per script and across the copy operation. Detaching a bound instance preserves its existing dependency owner through an optional declared library alias in the bindings. Revoked input or code bindings stay revoked; unused saved controls remain unchanged. Nested scripts use the resolved owner once. Independent copying of a detached node composes the forwarded maps into the new local document. Treat asset-closure or explicit scope-composition diagnostics as failed atomic edits. Do not replace a requested independent script with a rendered snapshot or an original-library link. This metadata extension does not establish Pencil round-trip rendering compatibility.

Generated browser nodes can select a captured resource namespace using browser_scope; browser ref overrides can use browser_override with separate user metadata. Copies capture declared aliases in script_bindings.browser_libraries, including the empty alias for the generator's own document and qualified nested imports. Browser scope v2 separately retains url_library for the URL's owning namespace, including a closed empty namespace when that document has no web resources. A metadata-only scope whose URL no longer matches uses this captured URL owner, not the previous active scope or the consumer's files. Re-copying composes both identities without rewriting code or URLs. Missing and empty browser URLs remain placeholders. Unknown aliases fail; local pages outside a captured namespace never open same-named consumer files. Legacy or reused components without captured URL ownership still produce a diagnostic. Custom binding and combined override composition remain unfinished.

Inherited scripts can override inputs, code or metadata independently before copying. Saved inputs retain their own namespace; a null ref uses the current code header's default. Omitted properties continue to inherit from the copied base definition, including later input or metadata changes. Use ordinary update/reset operations rather than editing private binding metadata. An explicit code or input update deliberately selects the caller's context for that field, even when its JSON is unchanged.
