# Browser snapshots

Use a browser node when the design needs a rendered web page. Ordinary frames and text continue to use native layout and Skia. Browser rendering needs a separately installed Chromium runtime. A missing runtime is an error with a setup command; rendering never downloads it automatically.

Set url, width, and height. Optional zoom, scrollX, and scrollY control the captured view. Current device IDs are desktop, phone, and tablet; other Pencil preset IDs still require compatibility work. HTTP(S), HTML data URLs, and about:blank are supported. Embedded URL credentials and arbitrary file URLs are rejected. Local test pages can be served over loopback HTTP.

For a local page, declare its resource directory with an edit operation such as {"op":"set_browser_resources","roots":[{"url":"file:///original/site/","path":"web"}]}. The original file directory URL must be canonical and end in a slash; path is relative to this document. This declaration uses the existing project read boundaries and cannot grant access outside them or into lazypencil's private data. A file browser node can then use file:///original/site/index.html?theme=dark#top. URL text is literal, including dollar signs. Only captured files from the owning document's declared namespace are served; unlisted file requests are denied. HTML, CSS and JavaScript retain their original URLs. Use {"op":"pack_browser_resources"} to save declared inputs into portable assets, and carry those assets with the .pen document. Setting roots to [] removes this document's declaration. These declarations and copy-context records are lazypencil metadata, separate from Pencil's node properties.

Captured resource contents and their owner are part of raster-cache and retained-page identities. A resource change retires the old DOM even when its node is outside the viewport; changing only dimensions still preserves DOM. Removing the declaration prevents file acquisition and retires the affected retained pages. A captured namespace provides bounded file responses; complete native file metadata, range/media loading, worklets, popups, and all worker bootstrap cases still need compatibility work.

Capture waits for document load, web fonts, decoded images, and two animation frames within a deadline. The host setting runtime.browser.wait_until defaults to load; network_idle additionally requires Chromium's networkIdle lifecycle notification for the current main-frame loader. It uses the same acquisition/render deadline. Ongoing requests can therefore time out instead of producing an early image. Neither policy guarantees settled application state, future requests, animations, workers, or every cross-origin frame. Inspect the returned image and acquisition metadata, including wait_until, rather than assuming a URL determines permanent pixels. Metadata redacts URL queries, fragments, credentials, and HTML data contents.

Use runtime.browser.ready_selector for a CSS readiness marker such as #app[data-state='ready']. An empty string disables it, including clearing an inherited selector. It applies to every browser acquisition using that configuration. selector_state defaults to visible; attached accepts the first matching main-document element even when hidden. Visible requires positive-area layout and Chromium visibility checks, including opacity zero and skipped content. It does not guarantee absence of occlusion or viewport intersection, and does not enter iframes or shadow roots. Zoom and instant scroll are applied before these checks and repeated as content appears. Selector syntax errors fail immediately; missing/hidden targets use the existing deadline and cancellation. Metadata records the selector and state. These are host capture preferences, not additional .pen node fields.

Use runtime.browser.additional_wait_ms for an extra 0–60,000 ms after load/selector readiness and before final font/image preparation. It defaults to zero and shares the acquisition/render deadline and cancellation. The host measures the interval, so page timers cannot shorten it. It does not predict later updates. Explicit zero clears an inherited wait; cached acquisitions do not wait again.

Set runtime.browser.animation_policy to paused to pause native document animations after readiness and the extra wait. The default running preserves normal playback. CSS animations, transitions and Web Animations use Chromium's document timeline; this is not a clock freeze for JavaScript timers, video, animated images or cross-process frames, and it does not seek to a fixed timestamp. Capture still waits for fonts, decoded images and two animation frames. An unchanged retained context stays paused on refresh. Policy changes invalidate acquisitions and can replace retained contexts; metadata records animation_policy. These settings inherit per field and belong in host configuration, not .pen node fields.

The CLI/MCP render path reuses an in-memory page raster until refresh is requested or the cache evicts it. Without a dedicated profile selection, each new acquisition there uses a fresh isolated browser context. Use refresh: true in the render tool to obtain a new acquisition. The result records its ID, timestamp, browser version, dimensions, zoom, scroll, scale, and PNG hash. A calculation snapshot and a page acquisition have different identities. The TUI opts into separate document/node page sessions, so its explicit capture refresh can preserve DOM state. Acquisition page_state records retained, id, reused, and retained_limit; it describes the acquisition, including when a cached image was originally captured. It does not promise that the browser is still alive. URL/device changes, eviction, idle expiry, failure, document rebinding and browser-policy changes can require a new state ID. TUI /play or Space in Preview periodically captures retained page DOM at a bounded maximum of 5 fps by default (1–10 fps through /play). Browser-only documents are supported. Slow rendering drops frames instead of queuing catch-up work. /pause or Space stops new frames; one requested frame may finish. Paused dependency polls reuse pixels and idle expiry still applies. Page frames reuse unchanged layouts and time-independent shader rasters. Page JavaScript and CSS use real browser time; /time seeks shader uniforms and does not rewind a page or run document script nodes on a clock. The hosted retained-page gate includes real browser/frame and Unix terminal checks for this path.

Use runtime.browser.network_policy for online (default) or offline web requests. Offline rejects HTTP(S) and WebSockets, including localhost and worker/child-frame requests. Captured local resources, data and about:blank keep their existing access boundaries. Remote main-document navigation fails. Changing the network policy invalidates acquisitions and restarts the page process for fresh and retained pages. Offline also restricts WebRTC to proxy routes, including its non-proxied UDP path; WebTransport uses the deny proxy. Metadata records network_policy. Explicit project online overrides inherited user offline. Broader protocol and host-wide egress controls remain unfinished. This is host configuration, not a .pen node field.

Captured runtime.browser settings control acquisition/launch deadlines and idle expiry; runtime.dynamic bounds the shared render duration and retained encoded-raster cache. Each acquisition reports its effective limits. Configuration changes invalidate old cached acquisitions, and a zero cache capacity disables reuse. These are host settings, independent of page content and document properties. Inspect the configuration and diagnostics when a deadline fails.

An explicitly created dedicated authentication profile can be selected with runtime.browser.profile in user configuration. Project settings may disable it with an empty string but cannot select one. The user manages login with runtime profile create/login and sets LAZYPENCIL_CHROMIUM to the same full Chrome/Chromium executable for both login and authenticated acquisition. Matching major versions are insufficient to mix full-browser and headless-shell stores. First use binds the profile to its canonical executable path; another path needs a new profile and login. Documents and agents do not import credentials. These acquisitions use new tabs in the profile's persistent browser context; TUI retention still controls each tab's DOM lifetime. Cookies, localStorage, IndexedDB and Cache Storage remain in private user data. Profile names and credentials are omitted from acquisition metadata, and shaders never use this state. Only one browser process may lease a profile; simultaneous TUI and separate MCP use still needs integration. Hosted verification and visible login acceptance are pending. Ordinary anonymous acquisitions retain their existing isolated-context behavior.

The captured image receives the node's transform, opacity, clipping, border, and supported effects. Browser JavaScript and CSS are evaluated by Chromium. WebGL shader jobs use a separate process. Do not invent a result when navigation, decoding, runtime startup, or a deadline fails. Remaining protocol restrictions, animation/frame controls, complete Pencil device-preset compatibility, authenticated-session integration, and full TUI lifecycle verification remain unfinished.
