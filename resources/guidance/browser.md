# Browser snapshots

Use a browser node when the design needs a rendered web page. Ordinary frames and text continue to use native layout and Skia. Browser rendering needs a separately installed Chromium runtime. A missing runtime is an error with a setup command; rendering never downloads it automatically.

Set url, width, and height. Optional zoom, scrollX, and scrollY control the captured view. Current device IDs are desktop, phone, and tablet; other Pencil preset IDs still require compatibility work. HTTP(S), HTML data URLs, and about:blank are supported. Embedded URL credentials and arbitrary file URLs are rejected. Local test pages can be served over loopback HTTP.

Capture waits for document load, web fonts, decoded images, and two animation frames within a deadline. The host setting runtime.browser.wait_until defaults to load; network_idle additionally requires Chromium's networkIdle lifecycle notification for the current main-frame loader. It uses the same acquisition/render deadline. Ongoing requests can therefore time out instead of producing an early image. Neither policy guarantees settled application state, future requests, animations, workers, or every cross-origin frame. Inspect the returned image and acquisition metadata, including wait_until, rather than assuming a URL determines permanent pixels. Metadata redacts URL queries, fragments, credentials, and HTML data contents.

Use runtime.browser.ready_selector for a CSS readiness marker such as #app[data-state='ready']. An empty string disables it, including clearing an inherited selector. It applies to every browser acquisition using that configuration. selector_state defaults to visible; attached accepts the first matching main-document element even when hidden. Visible requires positive-area layout and Chromium visibility checks, including opacity zero and skipped content. It does not guarantee absence of occlusion or viewport intersection, and does not enter iframes or shadow roots. Zoom and instant scroll are applied before these checks and repeated as content appears. Selector syntax errors fail immediately; missing/hidden targets use the existing deadline and cancellation. Metadata records the selector and state. These are host capture preferences, not additional .pen node fields.

The CLI/MCP render path reuses an in-memory page raster until refresh is requested or the cache evicts it. Each new acquisition there uses a fresh isolated browser context. Use refresh: true in the render tool to obtain a new acquisition. The result records its ID, timestamp, browser version, dimensions, zoom, scroll, scale, and PNG hash. A calculation snapshot and a page acquisition have different identities. The TUI opts into separate document/node page sessions, so its explicit capture refresh can preserve DOM state. Acquisition page_state records retained, id, reused, and retained_limit; it describes the acquisition, including when a cached image was originally captured. It does not promise that the browser is still alive. URL/device changes, eviction, idle expiry, failure, document rebinding and browser-policy changes can require a new state ID. TUI page retention is undergoing hosted verification; periodic page capture remains unfinished.

Captured runtime.browser settings control acquisition/launch deadlines and idle expiry; runtime.dynamic bounds the shared render duration and retained encoded-raster cache. Each acquisition reports its effective limits. Configuration changes invalidate old cached acquisitions, and a zero cache capacity disables reuse. These are host settings, independent of page content and document properties. Inspect the configuration and diagnostics when a deadline fails.

The captured image receives the node's transform, opacity, clipping, border, and supported effects. Browser JavaScript and CSS are evaluated by Chromium. WebGL shader jobs use a separate process. Do not invent a result when navigation, decoding, runtime startup, or a deadline fails. Persistent authenticated profiles, request restrictions, animation controls, complete Pencil device-preset compatibility, and full TUI lifecycle verification remain unfinished.
